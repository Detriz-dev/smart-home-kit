# Learning goal and objectives

### Learning goal

Become an AI-native product designer: a product designer who builds AI applications end to end.

### Learning objectives

**Engineering**

- Understand elements of frontend engineering system design
- Understand web technologies (HTML, CSS, JS, Type script, React, APIs)
- Apply basic / fundamental of web technologies (write code / design API)
- Understand software development lifecycle 
- Understand fundamental aspects of AI engineering
- Apply basic SLDC with AI

**Interface Design**

- Incorporate AI to design process

**Electronics**

- Understand electronics fundamentals
- Create simple module (using Raspberry py)

### Assumptions

DeTriz Smart Home Kit is a **learning project**, not a startup. The product is a realistic vehicle for practice. Success is measured by **what I learn**, not by revenue, users or market fit.

| #   | Assumption                      | What it means in practice                                                                                                                                                                                                                                 |
| --- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Not a business**              | No business goals, monetization, pricing or growth metrics. Decisions are made on learning value, not commercial value.                                                                                                                                   |
| 2   | **Problem space is given**      | No problem discovery or validation. The problem in the [product overview](../product-requirements/product-overview.md) and the [customer needs](../customer/customer-needs-JTBD.md) is treated as defined; the focus is on the **solution and delivery**. |
| 3   | **Practice the full lifecycle** | Every phase (design → code → test → deploy) is touched at least once, even if the result is small. Breadth of process over depth of features.                                                                                                             |
| 4   | **Start small, end to end**     | The first deliverable is small and taken all the way to a deployed product, not a half-built large system.                                                                                                                                                |
| 5   | **AI as a learning tool first** | Early on, AI is used to **explain, teach and review**. I write and understand the code myself.                                                                                                                                                            |
| 6   | **AI as a builder second**      | Later, AI agents do most of the building, so I can compare speed, quality and my own understanding with the earlier phase.                                                                                                                                |

### Learning areas

| Area                         | Topics                                                                                                                            |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Product specification**    | Product overview, user stories, acceptance criteria, story mapping, MoSCoW prioritization                                         |
| **Domain modelling**         | Domain-Driven Design: Ubiquitous Language, data model, lifecycles, events and commands                                            |
| **Design system**            | Figma, design tokens, Storybook, npm packaging                                                                                    |
| **Product documentation**    | Diátaxis, docs as a product (Docusaurus)                                                                                          |
| **Continuous development**   | Git, GitHub Actions (CI/CD), Conventional Commits, semantic versioning                                                            |
| **AI-assisted development**  | Context files and conventions, skills, MCP in the workflow (Figma, Claude Code), prompting, reviewing and testing AI-written code |
| **Frontend development**     | HTML, CSS, React, TypeScript, data visualization                                                                                  |
| **API design**               | REST, WebSocket, OpenAPI / AsyncAPI, a simulator that serves the same API                                                         |
| **Electronics and hardware** | Raspberry Pi, I2C and GPIO sensors, sensor physics                                                                                |
| **AI engineering**           | LLM APIs, tool calling, building an MCP server, Generative UI, structured output, evals                                           |
