Each concept in the kit has exactly one name, and that name is used everywhere: in the docs, the TypeScript types, the UI components and the copy they show. When you meet a term you don't know, look it up here.

Where the smart home industry already has a name for something (Matter, Google Home, Home Assistant, SmartThings), the kit uses it.

## Ownership

| Term        | Definition                                                                                                                                                                                                                                             | Example            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------ |
| **Account** | One person's sign-in to the kit. An Account owns Sites, Hubs and Standalone Devices. A Module belongs to its Hub's Account. An Account can also view Sites that other Accounts share with it, but can't change them or send commands to their Devices. | "anna@example.com" |

## Places

| Term           | Definition                                                                                                                                                                                                                | Example                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Site**       | A physical property the user monitors. The top of the location hierarchy. Each Site is owned by one Account, and one Account can own several Sites. The owner can share a Site with other Accounts, who can only view it. | "My flat", "Warsaw office", "Test lab"                                                    |
| **Space**      | A named area inside a Site where Devices are placed. It does not need walls.                                                                                                                                              | Living room, Meeting room A, Open-plan desk zone, Balcony                                 |
| **Space Type** | A category of Space, used for icons, defaults and comfort presets. The kit has a fixed list (in Example). Use Other when nothing fits.                                                                                    | Bedroom, Bathroom, Kitchen, Living room, Hallway, Garage, Office, Meeting, Outdoor, Other |
| **Floor**      | A grouping of Spaces within a Site, added only when Sites grow large.                                                                                                                                                     | Ground floor, Level 3                                                                     |

## Devices and Assets

Everything you pair is a Device. A Device connects in one of three ways (its Device Kind) and is one sort of thing (its Device Type). A Capability is not a Device, and neither is an Asset.

| Term                  | Definition                                                                                                                                                                                                                                         | Example                                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Device**            | Any hardware you pair. It has its own identity and Device Status, connects to the network (directly or through a Hub) and has Capabilities: what it reports and what you can change.                                                               | A Hub, a Climate Module, a kettle, a power strip                                                                                     |
| **Device Kind**       | _How_ a Device connects. Don't confuse it with Device Type, which says _what_ it is.                                                                                                                                                               | Hub, Module, Standalone Device                                                                                                       |
| **Hub**               | A Device that other Devices (Modules) connect through. In the kit, a small computer running the DeTriz Hub software: it reads its Modules, connects to the network over Wi-Fi and is placed in a Space. It usually has no Capabilities of its own. | The Raspberry Pi on the kitchen shelf                                                                                                |
| **Module**            | A Device that connects through a Hub, by wire or wirelessly. A wired Module is listed in the Hub's settings; a wireless one is found by a search. It belongs to its Hub's Space and Account.                                                       | A Climate Module plugged into the Hub, a Zigbee motion sensor                                                                        |
| **Standalone Device** | A Device that connects directly, without a Hub. It is placed in a Space itself.                                                                                                                                                                    | A Wi-Fi kettle, a power strip, motorized blinds, a thermostat                                                                        |
| **Device Type**       | _What_ a Device is, from one fixed list for every Device. Used for the icon and the default Device Name. Use Other when nothing fits.                                                                                                              | Hub, Climate, Light, Air Quality, Motion, Contact, Power, Smoke, CO, Kettle, Power strip, Blinds, Thermostat, Washing machine, Other |
| **Device Name**       | The name shown for one Device. Starts as a default name from its Device Type, and the user can rename it at any time. Renaming never changes the Device Type.                                                                                      | "Climate Module", renamed to "Kitchen climate"; "Kettle"                                                                             |
| **Device Token**      | A secret code that links a Hub or a Standalone Device to an Account. The user creates it in their Account and copies it into the Device's settings when setting the Device up. Modules don't need one: they belong to their Hub's Account.         | A long random code like `dev_7f3k…`                                                                                                  |
| **Connection Type**   | How a Device connects, shown for information only. No rule depends on it. Optional.                                                                                                                                                                | Wired, Wi-Fi, Zigbee, Thread, Bluetooth, Other                                                                                       |
| **Asset**             | A physical object in a Space that isn't connected itself, but that one or more Capabilities are about: Sensors watch it, Controls change it. It has no Device Status: a plant can't be paired, disconnected or faulty.                             | Office plant, front door, manual blinds, washing machine on a Power Sensor, desk lamp plugged into a socket                          |
| **Asset Type**        | A category of Asset, used for icons and default Metrics.                                                                                                                                                                                           | Plant, Tap, Door, Window, Appliance                                                                                                  |
| **Subject**           | What a Capability, and every Reading it produces, is about: either a Space (the room's air) or an Asset in that Space (the plant). Contact Readings are always about an Asset (a Door or Window); Motion, Smoke and CO Readings about the Space.   | Humidity → Bedroom; illuminance → Office plant; socket 2 Power → Desk lamp                                                           |

## Capabilities

A Capability is one thing a Device reports or lets you change. A Sensor only reports; a Control reports and can be changed.

| Term                 | Definition                                                                                                                                                                                                                | Example                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Capability**       | One thing a Device reports or lets you change. It has exactly one Metric and produces Readings. It is not a Device and has no status of its own: its Device's status applies. A Device can have several of the same kind. | The temperature Sensor on a Climate Module; socket 2 on a power strip                      |
| **Sensor**           | A Capability that only reports. The user can't change it.                                                                                                                                                                 | Temperature on a Climate Module, Smoke on a Smoke Module, Battery on a wireless Module     |
| **Control**          | A Capability that reports and can be changed with a command. It is a State Control or a Value Control, and has its own Allowed Commands.                                                                                  | Socket 1 Power, blinds Position, heating Setpoint                                          |
| **State Control**    | A Control whose value is one of its Metric's States. The UI names it by its Metric.                                                                                                                                       | Power (On/Off), Open / Close, Mode (Off/Heat), Operational State                           |
| **Value Control**    | A Control whose value is a number with a Unit, inside a range: a minimum, a maximum and a step. The UI names it by its Metric.                                                                                            | Setpoint 0–30 °C in steps of 0.5; Position 0–100 % in steps of 1                           |
| **Allowed Commands** | The commands one Control accepts. They depend on the Device's model, not on its Device Type: two kettles can allow different commands. A command that isn't allowed isn't offered in the UI.                              | A socket allows Turn on and Turn off; one kettle allows only Stop; a read-only kettle none |
| **Setpoint**         | The value a Device aims for, set with a Value Control. It is not a measurement: the measured value comes from a Sensor next to it.                                                                                        | Heating Setpoint 22 °C, while the Temperature Sensor shows 19.8 °C                         |

### Operational State

Some Devices run a task: a kettle boils water, a washing machine runs a programme. Operational State tells what that task is doing, and lets the user start and stop it. It follows Matter's Operational State.

| Term                  | Definition                                                                                                                                                                                                                                                                                                        | Example                                                                                    |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Operational State** | A State Control for a Device that runs a task. Its States are Stopped, Running, Paused and Error, and its commands are Start, Pause, Resume and Stop (each Device allows only some). A Device has at most one. A Device that runs a task has a Power Control only if the real device has a separate power button. | Kettle Running; washing machine Paused                                                     |
| **Phase**             | What kind of Running it is. Reported by the Device; the user can't choose it.                                                                                                                                                                                                                                     | Heating, Keeping warm (kettle); Washing, Rinsing, Spinning (washing machine)               |
| **Error Reason**      | Why the Operational State is Error. Either one of the kit's general reasons, or a reason the Device defines with its own label. If a Fault caused the Error, the Error Reason points to its Fault Code. The user can't choose Error: the Device reports it.                                                       | Unable to start or resume, Unable to complete, Command not valid in this state; "No water" |

## Measurements

A Capability either reports a number (22.4 °C) or tells which State something is in (On, Open, Running). Both are Readings.

| Term                | Definition                                                                                                                                                                                                                                                          | Example                                                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Metric**          | _What_ a Capability reports, from a fixed list. Each Metric is either a Measured Metric or a State Metric. VOC means volatile organic compounds (gases from paint, cleaning products and cooking). PM2.5 means fine dust particles. CO is carbon monoxide, not CO₂. | Temperature, CO₂, Battery, Setpoint, Power, Contact, Open / Close, Mode, Operational State, Motion, Smoke, CO                                                |
| **Measured Metric** | A Metric whose value is a number with a Unit.                                                                                                                                                                                                                       | Temperature, Humidity, Illuminance, CO₂, VOC, PM2.5, Battery, Setpoint, Position                                                                             |
| **State Metric**    | A Metric whose value is one of its own States: two or more. It has no Unit.                                                                                                                                                                                         | Power (On/Off), Contact (Open/Closed), Open / Close (Open/Closed/Opening/Closing), Mode (Off/Heat), Operational State, Motion, Smoke and CO (Detected/Clear) |
| **State**           | One of the values a State Metric can have. Each State Metric has its own list.                                                                                                                                                                                      | On, Off, Open, Closed, Opening, Closing, Detected, Clear, Running                                                                                            |
| **Unit**            | How a Measured Metric's value is expressed. Each Measured Metric has one standard Unit in the data; other display Units, like °F, are a formatting choice. %RH means relative humidity.                                                                             | °C, °F (display Unit), %RH, %, lx, ppm, ppb, µg/m³                                                                                                           |
| **Reading**         | One timestamped value from one Capability: Metric, value and time, plus the Unit for a Measured Metric. The value is a number or a State. For a Control, it is the value the Device reports, not the value the user asked for. Never changes once recorded.         | 22.4 °C in the Kitchen at 10:15:03; Front door Open at 08:02:11; Socket 1 On at 18:40:00                                                                     |
| **Detection**       | The time during which a Motion, Smoke or CO Sensor reports Detected. It starts with the first Detected Reading and ends with the next Clear Reading.                                                                                                                | Motion in the Hallway from 02:14 to 02:16                                                                                                                    |

## Alerts

| Term                    | Definition                                                                                                                                                                                                                                                                                                                                 | Example                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| **Alert Rule**          | A condition on one Capability that raises an Alert when it becomes true: the Reading is in a given State, or is above or below a value. Each rule has an Alert Level. The app's developer defines Alert Rules in code, and the UI can show them. A range is two rules: one "below" and one "above".                                        | "Living room below 20 °C" and "Living room above 30 °C" (Warning); "Front door Open" (Info); "Battery below 15 %" |
| **Built-in Alert Rule** | An Alert Rule every Smoke and CO Sensor has from the start: raise a Critical Alert when the Reading is Detected. It is on by default; the developer can turn it off.                                                                                                                                                                       | "Smoke Detected" on the Kitchen smoke Sensor                                                                      |
| **Alert**               | A message raised when an Alert Rule's condition becomes true. It stays Active until the condition is no longer true or the user closes it. A closed Alert never comes back: only a new start of the condition (after it ended) raises a new Alert. Only the Site's owner can close an Alert; Accounts the Site is shared with only see it. | "Smoke detected in Kitchen at 14:02"                                                                              |
| **Alert Level**         | How urgent an Alert is. Set on each Alert Rule; Built-in Alert Rules are Critical.                                                                                                                                                                                                                                                         | Critical (Smoke, CO), Warning (temperature too high), Info (front door Open)                                      |
| **Alert Status**        | Where an Alert is in its life. After an Alert is Closed, the Reading itself still shows the problem (Smoke Detected on the Device's card) until the condition ends.                                                                                                                                                                        | Active, Ended (the condition is no longer true), Closed (the user closed it while it was Active)                  |

## Statuses

### Device Status

A Device's status is three separate fields, each answering one question. Keeping them apart means a Device can be connected _and_ faulty at the same time, and an unpaired Device can never carry a Connection Status or a Fault.

| Field                 | Question it answers                              | Values                                     |
| --------------------- | ------------------------------------------------ | ------------------------------------------ |
| **Pairing Status**    | Is this Device registered to the Account?        | Unpaired, Pairing, Paired                  |
| **Connection Status** | Can we reach it right now? (Paired Devices only) | Connecting, Connected, Stale, Disconnected |
| **Fault**             | Is the hardware healthy? (Paired Devices only)   | None, or one or more Faults                |

### Pairing Status

| Term         | Definition                                                                                | Example                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **Unpaired** | The Device has been detected, but the user hasn't confirmed adding it to the Account yet. | A Climate Module listed in the Hub's settings, or found by a search, appears as "New device found" |
| **Pairing**  | First-time setup is running: the Device is joining the Account. Happens once per Device.  | The user taps "Add" and the Module is set up                                                       |
| **Paired**   | The Device belongs to the Account. Only now does it have a Connection Status.             | The Climate Module shows up in the Kitchen Space                                                   |

### Connection Status

| Term                  | Definition                                                                                                                                                                                                                                                                          | Example                                                                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Connecting**        | A paired Device is (re)establishing its connection. Happens after every power-up, restart or dropped link.                                                                                                                                                                          | The Hub boots after a power cut and reconnects its Modules                                             |
| **Connected**         | The Device is reachable and, if it has Capabilities, sending Readings.                                                                                                                                                                                                              | The Kitchen Climate Module sends a temperature every few seconds                                       |
| **Stale**             | A Connected Device sent no Reading within its Expected Interval. Only a Device with Capabilities can be Stale: a Hub without Capabilities never sends Readings of its own.                                                                                                          | "Last update 5 min ago" on the Light Module                                                            |
| **Expected Interval** | How long a Device can go without sending a Reading before it becomes Stale. The user sets it for each Device with Capabilities. Every such Device sends its current Readings at least once per Expected Interval, even when nothing has changed, so silence always means a problem. | 5 minutes for the Kitchen Climate Module; a closed front door still reports Closed every 5 minutes     |
| **Disconnected**      | The Device can't be reached. Its last known values are hidden: a disconnected icon shows in their place. The kit doesn't guess why: a silent Device can't tell.                                                                                                                     | The Hub was unplugged from the wall, a Module's wires came loose, or a wireless Module is out of range |

### Fault

| Term           | Definition                                                                                                                                                                                                                                       | Example                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **Fault**      | A hardware problem the Device reports about itself. Only Paired Devices have Faults. Independent of connection: a Device can be Connected and have a Fault. Separate from Operational State Error, but a Fault can cause one (see Error Reason). | CO₂ sensor failure, calibration issue    |
| **Fault Code** | A stable identifier for the kind of Fault, so the UI can show the right message and help.                                                                                                                                                        | `sensor_failure`, `calibration_required` |

### Command Status

A command to a Control doesn't take effect at once: the Device has to do it and report back. Until it does, the Control shows the command as Pending.

| Term          | Definition                                                                                                                      | Example                                                      |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| **Pending**   | The command was sent, and the Device hasn't reported the new value yet. The Control can't be used again until the command ends. | The user taps "Turn on" for socket 1; it shows "Turning on…" |
| **Confirmed** | A Reading shows the new value. The Control shows it as usual.                                                                   | Socket 1 reports On                                          |
| **Failed**    | The command was refused or timed out. The Control goes back to the last reported value and shows why.                           | "Couldn't turn on socket 1: the power strip didn't respond"  |
