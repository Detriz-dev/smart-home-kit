Every color, size and space in the kit's components comes from a **design token**: a named value, stored as a CSS variable that starts with `--shk-`. For example, `--shk-color-text-primary` is the color of main text, and `--shk-space-4` is 16px of space.

Because the components only use tokens, you can change the look of the whole kit by changing a few tokens, without touching the components.

## Loading the tokens

The tokens come in one CSS file. Load it once, at the root of your app, before the components' styles:

```tsx
import "@detriz-sh-kit/tokens/tokens.css";
import "@detriz-sh-kit/ui/styles.css";
```

You can then use the tokens in your own CSS too, so your screens match the kit:

```css
.my-panel {
  padding: var(--shk-space-4);
  background: var(--shk-surface-page);
  color: var(--shk-color-text-primary);
}
```

## In Figma

The same tokens are variables in the kit's [Figma library](https://www.figma.com/community/file/1700179982740576850/detriz-smart-home-kit), with the same names. The CSS name joins the Figma collection and the variable's path, with `--shk-` in front:

| Figma collection | Figma variable  | CSS variable                 |
| ---------------- | --------------- | ---------------------------- |
| `surface`        | `default`       | `--shk-surface-default`      |
| `color-border`   | `subtle`        | `--shk-color-border-subtle`  |
| `status`         | `danger/border` | `--shk-status-danger-border` |
| `palette`        | `gray/900`      | `--shk-palette-gray-900`     |

So a color you pick from a variable in Figma has a CSS variable with the same name in code.

## Two kinds of tokens

| Kind          | Says                      | Example                                                       | Use it?                                                  |
| ------------- | ------------------------- | ------------------------------------------------------------- | -------------------------------------------------------- |
| **Primitive** | A raw value               | `--shk-palette-gray-900` is `#272f34`                         | Rarely. Mostly to point a semantic token at a new value. |
| **Semantic**  | What the value is **for** | `--shk-color-text-primary` points to `--shk-palette-gray-900` | Yes. This is what components use.                        |

A semantic token points to a primitive one. Components use semantic tokens, so you can change what "primary text" means in one place, and every component follows.

## Changing a token

Set a token again in your own CSS. Where you set it decides how far the change reaches:

- **On `:root`**: the whole app.
- **On an element**: only that element and everything inside it.

```jsx live
<ColumnLayout>
  <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  {/* The same component, with two tokens changed for this part of the page only */}
  <div
    style={{
      "--shk-surface-default": "var(--shk-palette-gray-50)",
      "--shk-color-border-subtle": "var(--shk-palette-gray-300)",
    }}
  >
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </div>
</ColumnLayout>
```

In a stylesheet, the same change looks like this:

```css
.my-overview {
  --shk-surface-default: var(--shk-palette-gray-50);
  --shk-color-border-subtle: var(--shk-palette-gray-300);
}
```

Prefer pointing a token at another token, like `var(--shk-palette-gray-50)`, over a raw value like `#f6f9fb`. That keeps your colors in the same family as the kit's.

If you change a color token, check that text still has enough contrast: at least 4.5:1 for normal text and 3:1 for large text and icons.

:::note

The kit has one theme for now, on light backgrounds. There is no dark theme yet. If you place components on a dark background, check the contrast yourself.

:::

## Your own CSS and the kit

The components' styles are inside a CSS **cascade layer** called `detriz`. In CSS, styles outside a layer always win over styles inside one. So if your app has global styles that aren't in a layer, like a reset for every `button` or `ol`, they can change the kit's components.

To keep the kit's components looking right, put your global styles in a layer that comes **before** `detriz`:

```css
@layer reset, detriz;

@layer reset {
  ol {
    padding-left: 1.5rem;
  }
}
```

Changing tokens isn't affected by this: tokens are CSS variables, so setting them works anywhere.
