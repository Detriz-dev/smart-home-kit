# Shared types

Several components take the same kinds of values: a Metric, a Space Type, a Unit, a Connection Status. The kit exports one TypeScript type for each, named after its term in the [Glossary](/docs/domain-model/glossary). Use them in your own data, so your values always match what the components accept.

```tsx
import type {
  Metric,
  MeasuredMetric,
  StateMetric,
  State,
  AlertLevel,
  AlertRule,
  SpaceType,
  DeviceType,
  AssetType,
  DeviceKind,
  ConnectionType,
  CapabilityKind,
  CommandOf,
  CommandStatus,
  OperationalState,
  ErrorReason,
  UnitLabelUnit,
  ConnectionStatus,
  PairingStatus,
  FaultCode,
} from "@detriz-sh-kit/ui";
```

## Metric

What a Capability reports. A fixed list from the Glossary, in two kinds:

- **`MeasuredMetric`**: the value is a number with a Unit.
- **`StateMetric`**: the value is one of its own [States](#state) (two or more), with no Unit.

```ts
type MeasuredMetric =
  | "temperature"
  | "humidity"
  | "illuminance"
  | "co2"
  | "voc"
  | "pm25"
  | "battery"
  | "setpoint"
  | "position";
type StateMetric =
  | "power"
  | "contact"
  | "open-close"
  | "mode"
  | "operational-state"
  | "motion"
  | "smoke"
  | "co";
type Metric = MeasuredMetric | StateMetric;
```

| Value               | Kind     | Shows as          | Usual Unit or States                            |
| ------------------- | -------- | ----------------- | ----------------------------------------------- |
| `temperature`       | Measured | Temperature       | `celsius` or `fahrenheit`                       |
| `humidity`          | Measured | Humidity          | `percent-rh`                                    |
| `illuminance`       | Measured | Illuminance       | `lux`                                           |
| `co2`               | Measured | CO₂               | `ppm`                                           |
| `voc`               | Measured | VOC               | `ppb`                                           |
| `pm25`              | Measured | PM2.5             | `ug-m3`                                         |
| `battery`           | Measured | Battery           | `percent`                                       |
| `setpoint`          | Measured | Setpoint          | The Unit of what it sets: `celsius` for heating |
| `position`          | Measured | Position          | `percent`                                       |
| `power`             | State    | Power             | `on`, `off`                                     |
| `contact`           | State    | Contact           | `open`, `closed`                                |
| `open-close`        | State    | Open / Close      | `open`, `closed`, `opening`, `closing`          |
| `mode`              | State    | Mode              | `off`, `heat`                                   |
| `operational-state` | State    | Operational State | `stopped`, `running`, `paused`, `error`         |
| `motion`            | State    | Motion            | `detected`, `clear`                             |
| `smoke`             | State    | Smoke             | `detected`, `clear`                             |
| `co`                | State    | CO                | `detected`, `clear`                             |

`co` is carbon monoxide, not CO₂. `DetectionMetric` is the three Metrics that start a Detection: `motion`, `smoke` and `co`. [`DetectionStatus`](../readings/detection-status.mdx) takes a `DetectionMetric`.

**Used by:** [`SensorLabel`](../context/sensor-label.mdx) (`metric`, any Metric) and [`DeviceFaultStatus`](../status/device-fault-status.mdx) (the affected Sensor). [`SensorReading`](../readings/sensor-reading.mdx), [`ModuleCard`](../readings/module-card.mdx) and [`SpaceCard`](../readings/space-card.mdx) show numbers, so they take a `MeasuredMetric` only. `SensorLabelMetric` is the same type as `Metric` under another name.

## State

One of the values of a State Metric. Each Metric has its own list, and `StateOf` gives you the list for one Metric:

```ts
type ContactState = StateOf<"contact">; // "open" | "closed"
type OpenCloseState = StateOf<"open-close">; // "open" | "closed" | "opening" | "closing"
```

Use `StateOf` in your own data, so a Power Reading can never be `"open"`. `State` is every State of every State Metric.

**Used by:** [`StateValue`](../readings/state-value.mdx) (`metric` and `state`). The word shown for each State is in the exported `STATE_NAMES` map.

## Alerts

The types for [Alert Rules and Alerts](/docs/domain-model/glossary#alerts). You define Alert Rules in your code; the kit's components show them. A rule checks one Capability, and a range is two rules (one `below`, one `above`).

```ts
type AlertLevel = "critical" | "warning" | "info";
type AlertStatus = "active" | "ended" | "closed";

interface AlertRule {
  condition: AlertRuleCondition;
  alertLevel: AlertLevel;
  isBuiltIn?: boolean; // true for the Built-in Alert Rule of a Smoke or CO Sensor
}
```

`AlertRuleCondition` is one of two shapes, and TypeScript checks you use the right one for the Metric:

```ts
// A Measured Metric: above or below a value, in the Metric's standard Unit.
const tooWarm: AlertRule = {
  condition: { metric: "temperature", comparison: "above", value: 28 },
  alertLevel: "warning",
};

// A State Metric: one of that Metric's own States.
const doorOpen: AlertRule = {
  condition: { metric: "contact", state: "open" },
  alertLevel: "info",
};

// ❌ Type error: Power has no "open" State.
const wrong: AlertRule = {
  condition: { metric: "power", state: "open" },
  alertLevel: "info",
};
```

**Used by:** [`StateValue`](../readings/state-value.mdx) (`alertLevel`). [`AlertListItem`](../status/alert-list-item.mdx) uses `AlertLevel` and `AlertStatus`.

## SpaceType

A category of Space. A fixed list from the Glossary; use `other` when nothing fits.

```ts
type SpaceType =
  | "bedroom"
  | "bathroom"
  | "kitchen"
  | "living-room"
  | "hallway"
  | "garage"
  | "office"
  | "meeting"
  | "outdoor"
  | "other";
```

Each Space Type has one icon, in the exported `SPACE_TYPE_ICONS` map. See [`SpaceLabel`](../context/space-label.mdx#space-types) for the table.

**Used by:** [`SpaceLabel`](../context/space-label.mdx) (`spaceType`), and `SPACE_TYPE_ICONS` for a [`Card`](../layout/card.mdx)'s `icon`.

## DeviceType

What a Device is: one fixed list for every Device, from the Glossary. Use `other` when nothing fits. It replaces the earlier `ModuleType`.

```ts
type DeviceType =
  | "hub"
  | "climate"
  | "light"
  | "air-quality"
  | "motion"
  | "contact"
  | "power"
  | "smoke"
  | "co"
  | "kettle"
  | "power-strip"
  | "blinds"
  | "thermostat"
  | "washing-machine"
  | "other";
```

**Used by:** no component yet.

## AssetType

A category of Asset: a thing in a Space that Sensors watch. A Contact Sensor watches a `door` or `window`, and a Power Sensor watches an `appliance`.

```ts
type AssetType = "plant" | "tap" | "door" | "window" | "appliance";
```

**Used by:** [`AssetLabel`](../context/asset-label.mdx) (`assetType`), and `ASSET_TYPE_ICONS` for an icon on its own.

## DeviceKind

_How_ a Device connects. From the Glossary. Not the same as [`DeviceType`](#devicetype), which says _what_ it is.

```ts
type DeviceKind = "hub" | "module" | "standalone";
```

**Used by:** [`DeviceListItem`](../status/device-list-item.mdx) (`deviceKind`), which picks the icon from it: `router` for a Hub, `developer_board` for a Module, `devices` for a Standalone Device.

## ConnectionType

How a Device connects, for information only. No rule depends on it.

```ts
type ConnectionType =
  "wired" | "wifi" | "zigbee" | "thread" | "bluetooth" | "other";
```

**Used by:** no component yet.

## UnitLabelUnit

How a Metric's value is shown. See [`UnitLabel`](../readings/unit-label.mdx#units) for the symbols and what screen readers say.

```ts
type UnitLabelUnit =
  | "celsius"
  | "fahrenheit"
  | "percent-rh"
  | "percent"
  | "lux"
  | "ppm"
  | "ppb"
  | "ug-m3";
```

**Used by:** `UnitLabel` (`unit`), and every card's `unit` field. You choose the display Unit: for Temperature, `celsius` or `fahrenheit`.

## ConnectionStatus

Can a Paired Device be reached right now? See [`DeviceConnectionStatus`](../status/device-connection-status.mdx#states) for what each value means.

```ts
type ConnectionStatus = "connecting" | "connected" | "stale" | "disconnected";
```

**Used by:** `DeviceConnectionStatus` (`status`), `ModuleCard` (`connectionStatus`) and `SpaceCard` (each row's `connectionStatus`).

## PairingStatus

Does a Device belong to the Account? See [`DevicePairingStatus`](../status/device-pairing-status.mdx#states).

```ts
type PairingStatus = "unpaired" | "pairing" | "paired";
```

**Used by:** `DevicePairingStatus` (`status`).

## FaultCode

Which hardware problem a Device reports. It decides the message: the UI never shows the code itself. See [`DeviceFaultStatus`](../status/device-fault-status.mdx#states).

```ts
type FaultCode = "sensor_failure" | "calibration_required";
```

Fault Codes are written in `snake_case`, the way the Glossary and the API write them.

**Used by:** `DeviceFaultStatus` (`faultCode`), and the `faults` lists of `ModuleCard` and `SpaceCard`.

## Controls and commands

The types for [Capabilities and Controls](/docs/domain-model/glossary#capabilities).

```ts
type CapabilityKind = "sensor" | "state-control" | "value-control";
type CommandStatus = "pending" | "confirmed" | "failed";
```

`CommandOf` gives you the commands a Control's Metric can accept. Use it for a Control's Allowed Commands, so a Power Control can never list `"open"`:

```ts
type PowerCommand = CommandOf<"power">; // "turn-on" | "turn-off"
type BlindsCommand = CommandOf<"open-close">; // "open" | "close" | "stop"

// A kettle that can only be stopped:
const kettleCommands: CommandOf<"operational-state">[] = ["stop"];
```

| Control Metric      | Commands                           |
| ------------------- | ---------------------------------- |
| `power`             | `turn-on`, `turn-off`              |
| `open-close`        | `open`, `close`, `stop`            |
| `mode`              | `set-mode`                         |
| `operational-state` | `start`, `pause`, `resume`, `stop` |
| `position`          | `set-position`                     |
| `setpoint`          | `set-setpoint`                     |

**Used by:** no component yet.

## OperationalState

What a Device that runs a task is doing, following Matter. See [Operational State](/docs/domain-model/glossary#operational-state) in the Glossary.

```ts
type OperationalState = "stopped" | "running" | "paused" | "error";
type OperationalCommand = "start" | "pause" | "resume" | "stop";
```

When the state is `error`, an `ErrorReason` says why: one of the kit's general reasons, or the Device's own reason with a label. If a Fault caused it, `faultCode` points to it:

```ts
const noWater: ErrorReason = { code: "no-water", label: "No water" };
const brokenSensor: ErrorReason = {
  code: "unable-to-start-or-resume",
  faultCode: "sensor_failure",
};
```

The general reasons are `unable-to-start-or-resume`, `unable-to-complete` and `command-invalid-in-state` (`GeneralErrorReason`).

**Used by:** no component yet.

## Using them in your data

Type your own data with these types, and TypeScript checks it against the components for you:

```tsx
import type {
  ConnectionStatus,
  FaultCode,
  MeasuredMetric,
  Metric,
  UnitLabelUnit,
} from "@detriz-sh-kit/ui";
import { ModuleCard } from "@detriz-sh-kit/ui";

interface MyModule {
  name: string;
  connectionStatus: ConnectionStatus;
  faults: { faultCode: FaultCode; metric?: Metric }[];
  sensors: {
    metric: MeasuredMetric;
    value: number | null;
    unit: UnitLabelUnit;
  }[];
}

function MyModuleCard({ module }: { module: MyModule }) {
  return (
    <ModuleCard
      name={module.name}
      connectionStatus={module.connectionStatus}
      faults={module.faults}
      sensors={module.sensors}
    />
  );
}
```

If your data uses other words, for example an API that says `"online"` instead of `"connected"`, convert them once, where the data comes in, and keep the kit's types everywhere else.

## Component types

Every component also exports its own props type, named `<Component>Props`, like `ModuleCardProps`. Some export types for their parts too, like `ModuleCardSensor` and `SpaceCardReading`. Each component page lists them under **Props**.
