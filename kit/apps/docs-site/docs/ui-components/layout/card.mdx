# Card

The raised card the kit's cards share: a header strip in the page colour with an optional icon, title and a spot at the right, then a white body with your content and an optional footer, and a soft shadow. Put anything inside it. Use it to build your own cards that match the kit, like one card per room in a flat.

```jsx live
<div style={{ maxWidth: 320 }}>
  <Card
    title="Climate Module"
    headerEnd={<DeviceConnectionStatus status="connected" />}
    footer="Updated 2 min ago"
  >
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
</div>
```

:::tip[Try it]

The examples on this page are live. Change the code and the result updates as you type.

:::

A card fills the width of its parent, so the examples sit in a `div` with a `maxWidth`. In your app, the layout around the card sets its width.

## Import

```tsx
import { Card } from "@detriz-sh-kit/ui";
```

The component needs the kit's styles. Load them once, at the root of your app:

```tsx
import "@detriz-sh-kit/tokens/tokens.css";
import "@detriz-sh-kit/ui/styles.css";
```

See [Installation](/docs/get-started/installation) for how to install the packages.

## Basic usage

Give it a title and put the content inside:

```tsx
import { Card, SensorReading } from "@detriz-sh-kit/ui";

<Card title="Kitchen">
  <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
</Card>;
```

The examples below leave out the `import` line. In your app, you need it.

## When to use it

Use Card:

- **for your own cards**, when the kit has no ready-made one: a room with its plants, a Hub with its details
- **for a clickable tile** that opens another screen, like a room in an overview of the flat

Don't use it for:

- **All the Readings of one Module.** Use [`DeviceCard`](../readings/device-card.mdx).
- **The latest Readings of a Space.** Use [`SpaceCard`](../readings/space-card.mdx).
- **A heading for a group of cards.** Use [`ContentSection`](./content-section.mdx). A card's title isn't a heading.
- **Spacing without a surface.** Use [`StackLayout`](./stack-layout.mdx).

## Variants

A card is static, a link or a button. Which one depends on the props you pass:

| Variant | Props                | Tapping the card… |
| ------- | -------------------- | ----------------- |
| Static  | no `href`, `onClick` | does nothing      |
| Link    | `title` + `href`     | opens `href`      |
| Button  | `title` + `onClick`  | calls `onClick`   |

A clickable card looks the same as a static one until you use it: it turns light blue under the pointer and blue while pressed, and gets a blue ring when you reach it with the keyboard.

### Static

```jsx live
<div style={{ maxWidth: 320 }}>
  <Card title="Kitchen">
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
</div>
```

### Link

Point at the card, or press Tab to reach it.

```jsx live
<div style={{ maxWidth: 320 }}>
  <Card title="Kitchen" href="#kitchen">
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
</div>
```

### Button

```jsx live
<div style={{ maxWidth: 320 }}>
  <Card title="Kitchen" onClick={() => console.log("Open Kitchen")}>
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
</div>
```

## Making a card clickable

Pass `href` to make the card a link, or `onClick` to make it a button. Two rules, both checked by TypeScript:

- **A clickable card needs a `title`.** The title becomes the link's or button's text, so screen readers hear "Kitchen, link".
- **Pass `href` or `onClick`, not both.**

The whole card can be tapped, not only the title. Buttons and links you put inside the card still work on their own, but two tap targets in one card are easy to miss, so use them sparingly.

**Apps with a router.** `href` renders a plain link unless you wrap your app in `LinkProvider`. Do that once, and every link in the kit uses your router: see [Links and routing](/docs/get-started/links-and-routing).

## A flat as cards

One clickable card per Space gives an overview of the whole flat. Give each card its Space Type icon (see [Room icons](#room-icons)) and put the cards in a [`ColumnLayout`](./column-layout.mdx):

```jsx live
<ColumnLayout>
  <Card icon="countertops" title="Kitchen" href="#kitchen">
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
  <Card icon="bed" title="Bedroom" href="#bedroom">
    <SensorReading metric="temperature" value={20.1} unit="celsius" size="md" />
  </Card>
</ColumnLayout>
```

## Showing only some parts

Every part except the content is optional. Leave a prop out and its part isn't shown:

- No `title` and no `headerEnd`: no header at all.
- No `footer`: no footer.

```jsx live
<div style={{ maxWidth: 320 }}>
  <StackLayout>
    {/* Title only */}
    <Card title="Kitchen">
      <SensorReading
        metric="temperature"
        value={22.4}
        unit="celsius"
        size="md"
      />
    </Card>
    {/* Content only */}
    <Card>
      <SensorReading
        metric="temperature"
        value={22.4}
        unit="celsius"
        size="md"
      />
    </Card>
  </StackLayout>
</div>
```

## Room icons

Pass `icon` to show an icon before the title. It's 24px and takes the title's colour. It needs a `title`: without one, the icon isn't shown.

For a card about a Space, use the icon of its [Space Type](/docs/domain-model/glossary#places), so every screen shows the same icon for the same kind of room. Take it from `SPACE_TYPE_ICONS`, the map [`SpaceLabel`](../context/space-label.mdx) uses, instead of typing the name:

```tsx
import { Card, SPACE_TYPE_ICONS } from "@detriz-sh-kit/ui";

<Card icon={SPACE_TYPE_ICONS[space.spaceType]} title={space.name} …>
```

The map:

| Space Type  | `icon`        | Space Type | `icon`        |
| ----------- | ------------- | ---------- | ------------- |
| Bedroom     | `bed`         | Garage     | `garage_home` |
| Bathroom    | `bathtub`     | Office     | `desk`        |
| Kitchen     | `countertops` | Meeting    | `groups`      |
| Living room | `weekend`     | Outdoor    | `yard`        |
| Hallway     | `door_front`  | Other      | `home`        |

```jsx live
<div style={{ maxWidth: 320 }}>
  <StackLayout>
    <Card icon="bathtub" title="Bathroom">
      <SensorReading
        metric="humidity"
        value={64}
        unit="percent-rh"
        fractionDigits={0}
        size="md"
      />
    </Card>
    <Card icon="garage_home" title="Garage">
      <SensorReading
        metric="temperature"
        value={9.8}
        unit="celsius"
        size="md"
      />
    </Card>
  </StackLayout>
</div>
```

## Mapping your data

The card shows no data of its own: `title` is plain text, and the content is up to you. One rule from the [Glossary](/docs/domain-model/glossary) matters here:

- **Only Devices have a Connection Status.** For a card about one Module, put a `DeviceConnectionStatus` in `headerEnd`. For a card about a Space, leave `headerEnd` out: a Space has no status of its own, and showing one Module's status would suggest the whole room is fine or broken.

## Props

| Prop        | Type           | Default | Description                                                                                                                                          |
| ----------- | -------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `children`  | `ReactNode`    | –       | **Required.** The card's content, in the white body, top to bottom, 12px apart.                                                                      |
| `icon`      | `IconName`     | –       | An icon before the title, 24px, e.g. `countertops` for a Kitchen. Decorative: screen readers skip it. Shown only with a `title`.                     |
| `title`     | `string`       | –       | The card's name, plain text, e.g. "Kitchen". One line, ends with "…" when too long. **Required** when `href` or `onClick` is set.                    |
| `headerEnd` | `ReactNode`    | –       | Shown at the right end of the header, e.g. a `DeviceConnectionStatus` when the card is about one Module. Never shrinks.                              |
| `footer`    | `ReactNode`    | –       | Shown at the bottom in small grey text, e.g. "Updated 2 min ago". Components passed in keep their own styles.                                        |
| `padding`   | `"md" \| "sm"` | `"md"`  | The space inside the white body: `md` is 16px, `sm` is 8px. Use `sm` when the content is a [`List`](./list.mdx), whose rows bring their own padding. |
| `href`      | `string`       | –       | Makes the card a link to this address, e.g. `/spaces/kitchen`. Uses your router through [`LinkProvider`](/docs/get-started/links-and-routing).       |
| `onClick`   | `() => void`   | –       | Makes the card a button. Called when the card is tapped, clicked, or activated with Enter or Space.                                                  |

The types `CardProps`, `CardStaticProps`, `CardLinkProps` and `CardButtonProps` are exported too. `CardProps` is the union of the other three:

```tsx
import type { CardProps } from "@detriz-sh-kit/ui";
```

## Long text

A long title stays on one line and ends with "…". Point at it to see the full title. What's in `headerEnd` keeps its full width, so a status is never cut off.

```jsx live
<div
  style={{ maxWidth: 240, outline: "1px dashed var(--shk-palette-gray-300)" }}
>
  <Card
    title="Climate Module by the kitchen window"
    headerEnd={<DeviceConnectionStatus status="connected" />}
  >
    <SensorReading metric="temperature" value={22.4} unit="celsius" size="md" />
  </Card>
</div>
```

## Accessibility

What you get without doing anything:

- A static card with a title is a group named by its title, so screen readers announce "Kitchen, group" when entering it.
- A clickable card has one real link or button, named by the title. Tab stops once per card, and screen readers hear "Kitchen, link" instead of everything inside.
- Keyboard focus shows a 2px ring around the whole card. Enter opens a link card; Enter and Space activate a button card.
- The title is always shown as text, never as HTML. When it's shortened, the full title is in a tooltip.
- The icon is decorative, so screen readers skip it and read only the title.
- The blue hover fill is extra feedback only. The focus ring and pointer cursor don't rely on colour.

What's up to you:

- **A title that says where the card leads.** "Kitchen", not "More" or "Open". The icon doesn't replace it.
- **Headings.** The title isn't a heading. Put cards inside a [`ContentSection`](./content-section.mdx) so people can jump to the group.
- **Content order.** Put the content in the order people should read it.
- **Few tap targets inside a clickable card.** Every button inside it is one more Tab stop.

## Styling

| What                       | Token                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Header strip               | `--shk-surface-page`, at least `--shk-size-11` tall, `--shk-space-1` above and below, `--shk-space-4` at the sides |
| Body                       | `--shk-surface-default`, a `--shk-color-border-subtle` line on top                                                 |
| Border                     | `--shk-border-width-thin`, `--shk-color-border-subtle`                                                             |
| Shadow                     | `--shk-elevation-raised`                                                                                           |
| Corner radius              | `--shk-radius-16`                                                                                                  |
| Body padding               | `--shk-space-4` (16px), or `--shk-space-2` (8px) with `padding="sm"`                                               |
| Gap between parts          | `--shk-space-3` (12px)                                                                                             |
| Title, icon                | `--shk-color-text-primary`, `--shk-typography-body-*`                                                              |
| Icon size                  | `--shk-size-6` (24px)                                                                                              |
| Footer text                | `--shk-color-text-secondary`, `--shk-typography-caption-*`                                                         |
| Hover, pressed (clickable) | `--shk-action-secondary-bg-hover`, `--shk-action-secondary-bg-pressed`                                             |
| Focus ring (clickable)     | `--shk-action-focus`, `--shk-border-width-medium`                                                                  |

To change how it looks, set a [design token](../foundations/design-tokens.mdx) on a parent element. The change applies to everything inside that element, not only Card.
